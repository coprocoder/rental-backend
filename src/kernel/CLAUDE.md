# kernel — то, без чего не работает ни один модуль

⚠️ **Критерий попадания сюда ровно один: без этого не работает НИ ОДИН модуль.** Нужно
двум модулям из девяти — это не kernel, а модуль, от которого они оба зависят явно.
Каталог, названный «core» без такого критерия, через полгода содержит половину проекта.

| Файл | Что | Почему здесь |
|---|---|---|
| `db.ts` | пул, транзакция с тенантным контекстом | всё, что трогает данные |
| `errors.ts` | конверт ошибки и коды | ошибку бросает любой слой |
| `context.ts` | `Ctx`: кто и в каком тенанте действует | любой сценарий |
| `deps.ts` | `Deps`: БД, часы, очередь, журнал | любой сценарий |
| `clock.ts` | часы как зависимость | половина логики зависит от «сейчас» |
| `outbox.ts` | публикация эффекта в очередь | единственный способ сообщить наружу |
| `logger.ts` | структурные логи с redact | любой слой |
| `config.ts` | окружение, прочитанное один раз при старте | запуск |

## Тенантный контекст

⚠️ **`SET LOCAL app.tenant_id`, а не `WHERE tenant_id = …` в прикладном коде.** RLS в БД
не даст ошибиться, если запрос забудут отфильтровать. И `SET LOCAL`, а не `SET` —
сбрасывается по завершении транзакции и не протекает между запросами в пуле.

⚠️ **`tenantId` берётся ТОЛЬКО из сессии, ключа API или токена заказа — НИКОГДА из тела
запроса.** RLS доверяет этой переменной; подмена одного поля дала бы доступ к чужим данным.

⚠️ **`unscoped` — только для таблиц без RLS.** На практике это `tenant`, по которому слаг
витрины превращается в `tenant_id`. Так было не всегда, и это стоило неработающей витрины:
каталог читал через неё все свои таблицы, на машине разработчика приложение ходило под
владельцем БД (RLS не применяется) и всё работало, а в проде под `rental_app` те же
запросы возвращали ноль строк. **Разница между dev и прод была не в коде, а в РОЛИ.**

## Ошибки

⚠️ **`ApiError` — класс, а не объект с полем `code`.** У ошибок драйвера `pg` поле `code`
тоже есть; утиная проверка приняла бы `23505` за код API и отдала бы его клиенту.

⚠️ **`mapDbError` переводит только `23P01`** (нарушение `EXCLUDE`) — самую частую ошибку
в воронке бронирования, которая обязана приходить с альтернативами, иначе клиент уходит.
`23514` (CHECK) намеренно **не переводится**: в Nuxt-версии любой CHECK показывался как
«не хватает свободных единиц», и когда CHECK сработал на прайсе, прокат увидел сообщение
про склад на экране про деньги. CHECK ловится на месте вызова, где известно, какое
правило нарушено.

## Часы

⚠️ Не педантизм. Снятие броней, дедлайны подтверждения, сезоны, просрочка — всё зависит
от «сейчас». Уже стреляло: тест был зелёным утром и красным вечером, потому что строил
дни через `toISOString()` (UTC), а наличие считается в поясе филиала.

## Outbox

⚠️ **Таблица в Postgres, а не Redis.** Redis не участвует в транзакции Postgres: при
падении между COMMIT и записью в очередь заказ был бы создан, а уведомление потеряно.

⚠️ Ключ идемпотентности обязателен — колонка `NOT NULL` и уникальна в пределах тенанта.
Без него повторная запись того же эффекта создала бы второе письмо о том же заказе.
