# transport — общий HTTP-набор

То, что одинаково для всех модулей: сборка приложения, конверт ошибки, валидация.
Маршруты конкретного модуля живут **в модуле** (`modules/<имя>/http/`), а не здесь.

| Файл | Что |
|---|---|
| `app.ts` | фабрика приложения: CORS, correlation_id, health check, регистрация модулей |
| `errors.ts` | единственное место, где ошибка превращается в HTTP-ответ |
| `validate.ts` | `parse()` — схема valibot на границе |
| `types.ts` | тип `App` |

## Валидация

⚠️ **Схема обязательна, и это не стиль.** Fastify проверяет типы **ответов**, но никогда
тел запросов: «типизированный fetch» — не контракт. Непроверенные данные, дошедшие до
сценария, — именно тот баг, ради которого правило существует.

⚠️ **valibot, а не JSON Schema родного Fastify.** Схемы уже написаны (80 эндпоинтов), и в
них живёт нормализация: канонизация телефона происходит там же, где проверка.
Переписать их на другой валидатор значит переписать и нормализацию, потеряв по дороге
ровно то, что она предотвращает.

## Конверт ошибки

Один на весь API: `{ error: { code, message, details? } }`.
`message` для человека, `code` для кода — виджет реагирует на код, тексты ещё и переводятся.

⚠️ **Ожидаемые ответы предметной области не логируются как ошибки.** «Позицию только что
забрали» — самый частый ответ в воронке, и на уровне `error` он утопит настоящие сбои.

⚠️ **Тело непредвиденной ошибки наружу не уходит:** текст исключения способен содержать
фрагмент SQL и имена колонок. Клиенту — код и `correlationId`, по которому поддержка
найдёт запись. В Nuxt-версии наружу уезжал ещё и стек с абсолютными путями файлов сервера.

## Health check

⚠️ **Проверяет соединение с БД, а не отвечает 200 безусловно.** Экземпляр, потерявший
базу, обязан выпасть из балансировки; маршрут, который всегда отвечает «жив», оставляет в
ротации реплику, отдающую ошибки на каждый запрос — и балансировщик исправно шлёт туда
трафик.

## CORS

⚠️ Появляется только при выносе бэка: пока код жил внутри Nuxt, фронт и API были одним
origin. Разрешены ровно перечисленные в `CORS_ORIGINS`, плюс credentials — сессия
сотрудника ездит в cookie.

⚠️ **Пустой список означает «тот же origin», а НЕ «всем можно».** Ошибка в эту сторону
открывает публичный API любому сайту.

## Префикс `/api`

Сервис отвечает и на `/v1/…`, и на `/api/v1/…` — **псевдоним, а не вторая копия API**.
В браузере 84 вызова написаны как `/api/v1/…`: так их формировал Nuxt. Переписать их
значит тронуть 39 файлов и потерять откат одной переменной окружения.

⚠️ Убрать вместе с удалением `server/` из Nuxt.
