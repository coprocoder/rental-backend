# src — карта сервиса

Читать первым при любой правке кода. Как устроен модуль — `modules/CLAUDE.md`.

```
main.ts      сборка зависимостей и запуск — ЕДИНСТВЕННОЕ место, где создаётся пул
kernel/      то, без чего не работает ни один модуль
common/      контракт с фронтом и чистые утилиты (без зависимостей)
transport/   общий HTTP-набор: приложение, конверт ошибки, валидация
modules/     вертикальные срезы предметной области
```

## Слои и направление зависимостей

Вниз и только вниз. Проверяет `npm run arch`, девять правил.

```
http        маршрут, разбор запроса, код ответа, заголовки
   ↓
service     сценарий целиком  ← ЗДЕСЬ открывается транзакция, один раз
   ↓
domain      правила предметной области — БЕЗ ввода-вывода
   ↓
database    SQL
   ↓
kernel      пул, тенантный контекст, часы, журнал, outbox, ошибки
```

⚠️ **Транзакцию открывает `service`.** `domain` и `database` получают готовый
`PoolClient` и не знают, кто его открыл. Правило родилось из дефекта: каталог читал
шестью отдельными транзакциями — шесть независимых снимков, между которыми склад мог
измениться.

⚠️ **`domain` не делает ввод-вывод.** Не «не должен», а не может: правило в CI. Чистые
функции проверяются таблицей случаев за миллисекунды, а не поднятой базой — и поэтому
их действительно покрывают тестами.

⚠️ **В сигнатуре `service` нет объекта запроса.** Как только туда попадает `FastifyRequest`,
сценарий нельзя вызвать из воркера, из теста и из будущего мобильного приложения стойки.

## Что где лежит

| Нужно | Куда |
|---|---|
| новый эндпоинт | `modules/<модуль>/http/` + `service/` |
| новый SQL | `modules/<модуль>/database/` |
| правило предметной области | `modules/<модуль>/domain/` |
| тип | `modules/<модуль>/<модуль>.types.ts` |
| механизм без бизнес-смысла (часы, журнал, ошибки) | `kernel/` |
| чистая функция, нужная и фронту | `common/contract/` |
| чистая функция только для сервера | `common/utils/` |

⚠️ **`kernel` — не свалка.** Критерий: без этого не работает **ни один** модуль. Нужно
двум модулям из девяти — это не kernel, а модуль, от которого они оба зависят явно.

## Зависимости приходят параметром

I/O не импортируется, а передаётся в `Deps`: БД, часы, очередь, журнал.

```ts
export async function getCatalog(input: GetCatalogInput, deps: Deps) { … }
```

⚠️ **Часы в зависимостях — самое полезное здесь.** Половина логики зависит от «сейчас»:
снятие броней, дедлайны, сезоны, просрочка. Без подменяемых часов такие сценарии
тестируются только ожиданием, а «тест, который ждёт сутки» не пишут вовсе.
