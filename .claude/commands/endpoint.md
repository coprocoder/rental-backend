Перевезти эндпоинт: $ARGUMENTS

## 1. Снять эталон ДО правок

Без этого сверять будет не с чем, а «выглядит похоже» — не проверка.

```bash
cd ../rental && docker compose up -d
curl -s 'http://localhost:3100<путь>?...' > baseline/<имя>.json
```

Для мутаций одиночного вызова мало — нужен **сценарий** (создание → замена →
архивирование). Дефект замены будущей цены (19.23) нашёлся именно так.

## 2. Найти исходник и разобрать по слоям

Обработчик в `../rental/server/api/...` содержит всё сразу: валидацию, SQL, правила,
сборку ответа. Разложить:

| Что в обработчике | Куда здесь |
|---|---|
| схема valibot, разбор query/body | `modules/<модуль>/http/` |
| последовательность шагов, транзакция | `modules/<модуль>/service/` |
| правила без ввода-вывода | `modules/<модуль>/domain/` |
| SQL | `modules/<модуль>/database/` |
| типы | `modules/<модуль>/<модуль>.types.ts` |

⚠️ **Домен из `../rental/server/domain/` НЕ переписывать.** 10 200 строк и 322 теста
переезжают как есть — это главная экономия плана.

⚠️ **Транзакцию открывает `service`, один раз на сценарий.** Не `database`, не `http`.

⚠️ Если модуля ещё нет — сначала прочитать `src/modules/CLAUDE.md`, раздел «Добавление
модуля». Шаг «назвать вопрос, на который модуль отвечает» пропускать нельзя.

## 3. Зарегистрировать

`src/modules/registry.ts` — единственная правка вне каталога модуля.

## 4. Сверить

```bash
make check
diff <(python3 -m json.tool --sort-keys ../rental/baseline/<имя>.json) \
     <(python3 -m json.tool --sort-keys /tmp/new.json)
```

⚠️ Расхождение разбирать, а не подгонять эталон. Подогнанный эталон перестаёт быть
проверкой.
