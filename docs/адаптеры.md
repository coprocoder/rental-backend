# Адаптеры внешних систем

## Зачем слой

Домен **не зависит** от внешних API напрямую — это проверяется
правилом `domain-not-depend-on-integrations` в dependency-cruiser.

Причина конкретная: провайдеров эквайринга и фискализации будет
несколько, и переименование поля на их стороне не должно расходиться
по сорока файлам домена. Адаптер переводит их DTO в наш домен, и
менять при смене провайдера нужно только его.

## Уведомления

`server/integrations/notify.ts` + `notify.i18n.ts`.

Каналы с деградацией: мессенджер → почта → SMS. Мессенджер дешевле
и надёжнее, SMS дороже и нужен только для критичного.

⚠️ Отправка идёт **через outbox**, а не из обработчика запроса:
упавший SMTP не должен ронять оформление заказа. Повторы с нарастающей
паузой, после шести неудач — `dead`.

## Telegram

Вебхук `POST /api/v1/public/telegram/{slug}` — свой на каждого тенанта.

Связывание чата с клиентом: deep-link со стартовым payload'ом. Клиент
нажимает «начать», бот получает `/start <payload>` и понимает, кто это,
без ввода номера вручную.

## MAX

`POST /api/v1/public/max/{slug}`.

| Параметр | Значение |
|---|---|
| База | `https://platform-api2.max.ru` |
| Авторизация | заголовок `Authorization: <token>` (без `Bearer`) |
| Отправка | `POST /messages` |
| Проверка бота | `GET /me` |
| Событие старта | `bot_started` с полем `payload` |
| Deep-link | `https://max.ru/{bot}?start={payload}` |

⚠️ `payload` — не более 128 символов.

Открытый вопрос, который закрылся исследованием: deep-link со стартовым
payload'ом в MAX **есть**. До проверки в плане была запасная схема
со связыванием по короткому коду — она оказалась не нужна.

## Эквайринг и фискализация

Пока не реализованы. Заложено:

- **идемпотентность по ключу платежа.** Вебхук эквайринга может прийти
  дважды, с задержкой или не в том порядке. Это самое частое место,
  где такие системы теряют деньги и брони;
- **адаптер обязателен** с первого провайдера, а не «когда появится
  второй»: переписывать домен под второго дороже, чем сразу развести.

## Объектное хранилище

MinIO локально, S3 в РФ в проде — один и тот же S3 API.

⚠️ MinIO под AGPL, поэтому **только локально**. Переезд на SeaweedFS
(Apache 2.0) запланирован отдельным пунктом.

## Redis

Очередь отправки и rate limiting по ключу API.

⚠️ Лицензия RSAL/SSPL. Запрет касается продажи Redis как сервиса —
внутреннее использование как очереди допустимо. Переезд на Valkey (BSD)
запланирован, и это строка в `docker-compose.yml`: API совместим.
