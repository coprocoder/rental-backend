# Слои и модули rental-backend

```
http → service → domain → database → kernel → PostgreSQL
```

⚠️ **Транзакцию открывает `service`**, ровно один раз на сценарий. `domain` и `database`
получают готовый `PoolClient`. Правило родилось из дефекта: каталог читал шестью
отдельными транзакциями — шесть независимых снимков, между которыми склад мог измениться.

⚠️ **`domain` не делает ввод-вывод** — правило `domain-no-io` в CI. Чистые функции
проверяются таблицей случаев за миллисекунды, а не поднятой базой.

⚠️ **В сигнатуре `service` нет объекта запроса.** Как только туда попадает
`FastifyRequest`, сценарий нельзя вызвать из воркера, из теста и из мобильного приложения
стойки.

## Модуль

```
modules/<имя>/
  http/  service/  domain/  database/
  <имя>.types.ts    строки БД (*Row) и доменные формы
  index.ts          ← единственное, что видят другие модули
```

Наружу уходят доменные типы, а не строки таблиц: привязка соседа к именам колонок
означает, что переименование колонки ломает чужой модуль.

## Владение данными

Писать в таблицу может только модуль-владелец; читать — любой, обычным `JOIN`.
Учебное «каждый владеет своими таблицами» на этой схеме неприменимо: `category` читают
9 областей, `inventory_variant` — 8.

Подробно: `docs/архитектура.md` (со схемами), `src/modules/CLAUDE.md`.
