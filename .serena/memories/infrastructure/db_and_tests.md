# База и тесты rental-backend

⚠️ **Схема и миграции живут в `../rental/`** (`drizzle/`), сюда НЕ дублируются. Одна из
копий стала бы ложью в первый же день.

```bash
cd ../rental && docker compose up -d postgres   # порт 55432
DATABASE_URL="postgres://rental:rental@localhost:55432/rental" make dev
```

## Чем проверять

| Слой | Чем | На чём |
|---|---|---|
| domain | unit | чистые функции, подменяемые часы |
| database | интеграционные | **реальный Postgres**, транзакция с откатом |
| service | сценарные | реальный Postgres, без HTTP |
| http | контрактные | `app.inject()`, deps подменены |

⚠️ **Реальный Postgres обязателен** для слоя database: `EXCLUDE USING GIST` и RLS в
эмуляторах не существуют, и тест, проходящий без них, не доказывает ничего.

⚠️ **Тест изоляции тенантов под владельцем схемы бессмыслен** — владелец обходит RLS.
Переключаться внутри транзакции: `SET LOCAL ROLE rental_app`.

## Сверка с эталоном

Главная проверка переезда, а не тесты. Эталон в `../rental/baseline/`, снят с Nuxt-стенда
до правок. Сравнивать разобранным JSON с сортировкой ключей.

⚠️ Расхождение — находка. Так найден дефект 19.38: `SELECT DISTINCT` без `ORDER BY`
возвращал строки в порядке, зависящем от плана выполнения.
