# 02. Слои: кто что делает и кто открывает транзакцию

Открывается при написании любого кода. Короткий документ намеренно.

---

## Пять слоёв

```
transport   HTTP: маршрут, разбор запроса, код ответа, заголовки
    ↓
usecase     сценарий целиком: «создать заказ», «выдать снаряжение»
    ↓       ← ЗДЕСЬ открывается транзакция
domain      правила: цены, наличие, подбор, переходы статусов
    ↓
gateway     SQL
    ↓
kernel/db   пул, тенантный контекст, миграции
```

`shared` стоит сбоку — типы и чистые функции, общие с фронтом, не зависят ни от чего.
`integrations` на уровне gateway: туда ходят из usecase, **никогда из domain**.

## Что можно на каждом слое

| Слой | Знает про | Не знает про |
|---|---|---|
| transport | HTTP, схемы валидации, коды ошибок | бизнес-правила, SQL |
| usecase | последовательность шагов, транзакцию | HTTP, конкретный SQL |
| domain | правила предметной области | HTTP, откуда пришли данные |
| gateway | SQL и схему таблиц | HTTP, зачем спросили |
| kernel | соединения, часы, журнал | предметную область |

⚠️ Проверяется `dependency-cruiser`, семь правил — список в `06-ЭТАПЫ.md`.

## Новый слой: usecase

Его сейчас нет, и это главное изменение. Сегодня сценарий живёт в обработчике HTTP:
`public/orders.post.ts` — **341 строка кода**, где вперемешку валидация, девять вызовов
домена и сборка ответа. Следствия конкретные:

- сценарий нельзя переиспользовать — мобильное приложение стойки пойдёт тем же путём;
- его нельзя протестировать, не подняв HTTP;
- при выносе бэка его придётся выковыривать из обработчика.

```ts
// modules/booking/usecase/create-order.ts
export async function createOrder(
  input: CreateOrderInput,   // уже провалидировано транспортом
  ctx: Ctx,                  // { tenantId, actor, correlationId }
  deps: Deps,                // { db, clock, notifier }
): Promise<CreateOrderResult> {
  return deps.db.tx(ctx.tenantId, async (c) => {      // ← транзакция здесь
    const price = await priceFor(c, …)                // домен
    await reserve(c, …)                               // домен
    const id = await insertOrder(c, …)                // gateway
    await publish(c, 'order.created', { id })         // outbox в той же транзакции
    return { id, price }
  })
}
```

⚠️ **В сигнатуре нет ни `event`, ни `Request`, ни `PoolClient`.** `Ctx` собирает транспорт;
транзакцию открывает usecase. Как только сюда попадает объект запроса, слой перестаёт быть
переносимым — и это первое, что ломается на практике.

## Кто открывает транзакцию

**Usecase, ровно один раз на сценарий.** Domain и gateway получают готовый `PoolClient` и
не знают, кто его открыл.

⚠️ Правило появилось из дефекта: каталог читал **шестью отдельными транзакциями** —
`query(tenantId, …)` открывает свою на каждый вызов, — то есть шесть независимых снимков
данных, между которыми склад мог измениться. Витрина могла показать вариант, которого в
списке сезонов уже нет. Исправлено, но само правило формулируется именно так.

⚠️ **Тенантный контекст ставится вместе с транзакцией.** `SET LOCAL app.tenant_id` внутри
неё, `tenantId` — только из сессии или ключа API, **никогда из тела запроса**. RLS доверяет
этой переменной; подмена одного поля дала бы доступ к чужим данным.

## SOLID на практике этого проекта

Не пересказ принципов, а что они означают здесь.

**S — одна ответственность у модуля.** `pricing` отвечает «сколько стоит», `availability` —
«свободно ли». Признак нарушения: чтобы ответить, модуль лезет писать в чужие таблицы.

**O — расширение без правки.** Новый эквайринг = новый адаптер, домен не трогаем.
Это уже правило CI: домену запрещено импортировать `integrations`.

**L — подстановка.** Адаптеры одного вида взаимозаменяемы, потому что домен видит наш тип,
а не их DTO. Провайдеров будет несколько — это не гипотеза, а план (17.1–17.3).

**I — узкий интерфейс.** Наружу уходит `booking.public.ts`, а не всё, что модуль умеет.

**D — инверсия зависимостей.** I/O приходит параметром `deps`, а не импортом.

```ts
interface Deps {
  db: { tx<T>(tenantId: string, fn: (c: PoolClient) => Promise<T>): Promise<T> }
  clock: () => Date          // ⚠️ не педантизм, см. ниже
  notifier: { publish(c: PoolClient, kind: string, payload: object): Promise<void> }
}
```

⚠️ **Часы в зависимостях — самое полезное здесь.** Половина логики зависит от «сейчас»:
снятие броней, дедлайны подтверждения, сезоны, просрочка. Без подменяемых часов эти
сценарии тестируются только ожиданием — а «тест, который ждёт сутки» не пишут вовсе.
У нас уже есть тест, который был зелёным утром и красным вечером, потому что строил дни
через `toISOString()` (UTC), а наличие считается в поясе филиала.

## DRY: про знание, а не про текст

**Настоящее нарушение** — одно правило в двух местах, которые обязаны меняться вместе.
Пример из нашего кода: матрица прав имела клиентское «зеркало», копии разошлись, опечатка
в названии права молча возвращала `false` и прятала пункт меню. Теперь одна таблица в
`shared/permissions.ts` и union-тип, который ловит опечатку компилятором.

**Ложное срабатывание** — два похожих `SELECT` в разных модулях. Они отвечают на разные
вопросы и изменятся по разным причинам; сведение их в одну «универсальную» функцию с
пятью флагами связывает модули навсегда.

⚠️ Проверка одним вопросом: **изменится ли второе место, когда изменится первое?** Да —
выносить. Нет — оставить, это совпадение формы.

## Чистый код: три правила, которые тут реально работают

**Комментарий объясняет ПОЧЕМУ, а не ЧТО.** В этом проекте комментарии — главный носитель
знания: «⚠️ SET LOCAL, а не SET — сбрасывается по завершении транзакции», «⚠️ Соседние
даты считаются ТОЛЬКО при отказе: это перебор окон». Такое из кода не вычитать.

**Имя = вопрос предметной области.** `expireUnconfirmed`, `nearbyWindows`, `pickChannel` —
понятно без чтения тела. `process`, `handle`, `manager` — нет.

**Функция делает одно.** Не про длину: `quote` в 160 строк читается, потому что это
последовательность понятных шагов. А 341 строка `orders.post.ts` — не читается, потому что
там три разные обязанности сразу.

## Тестирование по слоям

| Слой | Чем | На чём |
|---|---|---|
| domain | unit, быстрые | чистые функции, подменяемые часы |
| gateway | интеграционные | **реальный Postgres**, транзакция с откатом |
| usecase | сценарные | реальный Postgres, без HTTP |
| transport | контрактные | поднятое приложение, сверка с эталоном |

⚠️ **Реальный Postgres обязателен.** `EXCLUDE USING GIST` и RLS в эмуляторах не существуют,
и тест, проходящий без них, не доказывает ничего.

⚠️ **Тест изоляции тенантов под владельцем схемы бессмыслен** — владелец обходит RLS, и
тест зеленеет на открытой базе. Переключаться внутри транзакции: `SET LOCAL ROLE
rental_app`.

⚠️ Сейчас **ни один из 322 серверных тестов не импортирует HTTP-слой** — они про домен,
шлюз и схему. Это ценное свойство: при переезде они не меняются. Не потерять его, начав
писать тесты через поднятый сервер там, где хватает usecase.
